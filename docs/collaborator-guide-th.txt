ส่วนที่ 1  repo นี้คืออะไร
---------------------------------------------------------------------

- เป็นที่รวมเนื้อหา General Surgery (G1-G4) ของ MDCU ปี 4
  แต่ละคนวนไม่ครบทุก G เลยเอาของทุกคนมารวมกัน ทุกคนจะได้ครบ 4 G
- ตอนนี้ยังไม่รับ subspecialty (Colorectal, Neuro, CVT, Plastic, Uro, Ped)
  Colorectal เป็น subspecialty ไม่ใช่ G
- ทั้งหมดอยู่บน GitHub เป็น private repo ชื่อ playerplayrh/surgery-year-4
- คุณไม่ต้องพิมพ์ code เอง ให้ Claude Code ทำแทน คุณแค่คุยกับมันเป็นภาษาคน

คำศัพท์ที่ต้องรู้ (อ่านครั้งเดียวพอ)
  repo (repository) = โฟลเดอร์งานของกลุ่มที่เก็บไว้บน GitHub
  clone            = copy repo ลงเครื่องเรา ทำครั้งเดียว
  main             = ฉบับหลักที่ทุกคนใช้ ห้ามแก้ตรงๆ
  branch           = ฉบับร่างของเรา แยกจาก main แก้ได้ตามใจ ไม่กระทบคนอื่น
  commit           = กด save พร้อมข้อความว่าแก้อะไร
  push             = ส่ง save ในเครื่องขึ้น GitHub
  pull             = ดึงของใหม่จาก GitHub ลงเครื่อง
  PR (Pull Request)= "ขอเอาฉบับร่างของเรารวมเข้า main" ให้คนอื่นดูได้ก่อน
  merge            = รวมฉบับร่างเข้า main แล้ว (ทุกคนเห็น)
  validate / check = โปรแกรมตรวจอัตโนมัติ (scripts/validate.py) ขึ้นเขียว = ผ่าน แดง = มีปัญหา
  Claude Code      = Claude เวอร์ชันที่อ่าน/เขียนไฟล์ในเครื่องเราได้ และสั่ง git ให้ได้
  slash command    = คำสั่งที่ขึ้นต้นด้วย / เช่น /jobs พิมพ์ในช่องแชตของ Claude Code

ส่วนที่ 2  ตั้งค่าครั้งแรก (ทำครั้งเดียว ประมาณ 20-30 นาที)
---------------------------------------------------------------------

ขั้นที่ 0  รับคำเชิญ (invitation)
  - เช็กอีเมลที่ผูกกับ GitHub หรือเข้า https://github.com/playerplayrh/surgery-year-4
  - กด Accept invitation ถ้าเข้าหน้า repo ได้ = เรียบร้อย

ขั้นที่ 1  ลงโปรแกรม
  Mac:
    1. Claude desktop app (https://claude.ai/download) ใช้แท็บ "Code"
    2. เปิดแอป Terminal แล้วพิมพ์ทีละบรรทัด (ถ้ายังไม่มี Homebrew ให้ถามเจ้าของ repo):
         xcode-select --install
         brew install gh
       (xcode-select ให้ทั้ง git และ python3 มาด้วย)
  Windows:
    1. Claude desktop app เหมือนกัน
    2. ลง Git for Windows (https://git-scm.com), GitHub CLI (https://cli.github.com),
       และ Python 3 (https://python.org ติ๊ก "Add python to PATH" ตอนลง)
    หมายเหตุ: /inbox ยังใช้บน Windows ไม่ได้ (ใช้คำสั่ง textutil ที่มีแค่บน Mac)
    แต่งานอื่นทั้งหมดใช้ได้

ขั้นที่ 2  login GitHub (แบบเปิด browser ไม่ต้องใช้ token)
  ใน Terminal พิมพ์:
       gh auth login
  เลือกตามนี้: GitHub.com -> HTTPS -> Yes (authenticate Git) -> Login with a web browser
  มันจะให้รหัส 8 ตัว เอาไปใส่ใน browser แล้วกด Authorize
  จากนั้นพิมพ์:
       gh auth setup-git

  ห้ามส่ง password หรือ token ให้ใคร รวมถึงห้ามพิมพ์ลงในแชตกับ Claude
  (ถ้าเคยสร้าง token เอง: ต้องเป็นแบบ "classic" และติ๊ก repo
   แบบ fine-grained ใช้กับ repo ของคนอื่นไม่ได้)

ขั้นที่ 3  clone repo ลงเครื่อง
  เลือกที่เก็บ เช่น Documents แล้วพิมพ์:
       cd ~/Documents
       gh repo clone playerplayrh/surgery-year-4

ขั้นที่ 4  เปิดใน Claude Code
  เปิด Claude app -> แท็บ Code -> เลือกโฟลเดอร์ surgery-year-4 ที่เพิ่ง clone
  พิมพ์ทดสอบ:  "ช่วยเช็กว่าตั้งค่าครบไหม: git, gh, python3 และ validate ผ่านไหม"
  Claude จะรันให้และบอกผล

ส่วนที่ 3  ใช้งานประจำ (แค่คุยกับ Claude)
---------------------------------------------------------------------

ก่อนเริ่มทุกครั้ง พิมพ์:
  "ดึงของล่าสุดจาก main แล้วสร้าง branch ใหม่ให้หน่อย"
  (Claude จะ pull แล้วสร้าง branch ให้ ห้ามทำงานบน main ตรงๆ)

A. เพิ่มเนื้อหาของตัวเอง (โน้ต, facts, case, exam ที่จำได้)
   1. ลบข้อมูลคนไข้ก่อน (ดูส่วนที่ 5)
   2. paste ลงแชต พร้อมบอกว่าเป็น G ไหน เช่น
        "G3 นี่คือ facts เรื่อง cholecystitis ที่จดตอน ward ช่วยแปลงเข้า repo"
      เขียนรกๆ ได้ ไทยปนอังกฤษได้ Claude จะเก็บต้นฉบับไว้ที่ raw/<ชื่อคุณ>/ แบบไม่แก้คำ
      แล้วแปลงเป็นไฟล์ตาม template
   3. ถ้าเป็น exam Claude จะถามทีเดียว: set code, ปี, rotation, รูปแบบ (mcq/meq/osce)
      และเฉลยมาจากไหน (official / recalled / ให้ AI หา)
   4. อ่านผลที่ Claude ทำ ถ้าโอเค พิมพ์:
        "validate แล้ว commit, push, เปิด PR ให้หน่อย"
   5. รอ check ขึ้นเขียว แล้วให้เพื่อนอีกคนกดดู (ส่วนที่ 6)

B. อ่าน / ทบทวน
   ถาม Claude ได้เลย เช่น
     "สรุป approach to jaundice จาก repo"
     "ทำ quiz 10 ข้อ G1 จาก facts ที่มี"
     "เปรียบเทียบ cholecystitis กับ cholangitis"
   เริ่มอ่านเองได้ที่ synthesis/, digests/, facts/<topic>/_merged.md, textbook/
   ทุกไฟล์มี status: ai-generated = ยังไม่มีคนตรวจ อย่าเชื่อ 100%
   human-verified = มีคนเทียบกับตำราหรืออาจารย์แล้ว

C. งานใหญ่ (extraction queue): /jobs
   ใช้สำหรับงานยาว เช่น แกะข้อสอบเก่า (AC) หรือตำรา ทีละชิ้น
   1. พิมพ์  /jobs   Claude จะโชว์ dashboard ว่ามีงานอะไรบ้าง (วิธีอ่านดูส่วนที่ 4)
   2. เลือกงานที่ status เป็น todo ทำอันไหนก่อนก็ได้ priority 1 = แนะนำให้ทำก่อน
   2.5 เอาไฟล์ต้นฉบับ (ไม่ต้องใช้ rclone)
      - ครั้งแรกครั้งเดียว: ขอเจ้าของ repo ให้แชร์โฟลเดอร์ Google Drive "Surgery Group" ให้คุณ
      - ทุกงานมีโฟลเดอร์ของตัวเองใน Drive: Surgery Group/job-files/<ชื่องาน>/
        ข้างในมี paper (ข้อสอบ) + key (เฉลย) + READ ME บอกว่าไฟล์ไหนคืออะไร
        bank ใหญ่ถูกตัดเป็นไฟล์ละ 30 หน้าแล้ว ไม่ต้องโหลดทั้งเล่ม
        เฉลยที่ใช้ร่วมกันหลายงานอยู่ใน job-files/_shared-keys/
      - Claude จะให้ลิงก์โฟลเดอร์ (หรือกดคำว่า "files" ใน dashboard)
        คลิกขวาที่โฟลเดอร์ -> Download -> unzip แล้วบอก Claude ว่าเซฟไว้ที่ไหน
        เช่น "ไฟล์อยู่ที่ Downloads/exam-mdcu76-gen-c-mcq"
      - ห้ามแก้ เปลี่ยนชื่อ ย้าย หรือลบไฟล์ใน job-files/ และห้ามเอา PDF ใส่ใน repo
   3. Claude จะ save ทุก 1 หน้า หรือทุก 5 ข้อ แล้ว push ขึ้น GitHub เอง
      แชตหลุด / แบตหมด / ปิดเครื่อง ไม่เป็นไร เสียงานแค่ไม่เกิน 1 ขั้น
   4. จะหยุด: พิมพ์ "หยุดตรงนี้" Claude จะคืนงานเป็น todo และจดที่คั่นไว้
      คนต่อไป (หรือตัวคุณเอง) พิมพ์ /jobs แล้วเลือกงานเดิม Claude จะทำต่อจากที่คั่น
   5. ทำเสร็จ: Claude จะ validate และเปิด PR ชื่อ "Job <id>"

   สำคัญ: งานที่ status เป็น on-hold ห้ามเริ่ม และห้ามเปลี่ยน status เอง
   มีแค่เจ้าของ repo (playerplayrh) ที่ปลด on-hold ได้
   (ตอนนี้งานแกะข้อสอบทั้งหมดยัง on-hold อยู่)

D. Google Drive inbox: /inbox
   ใช้ดึงไฟล์ที่เพื่อนที่ไม่มี GitHub อัปไว้ใน Drive เข้า repo
   ต้องตั้งค่า rclone ก่อน ปกติเจ้าของ repo เป็นคนรัน ถ้าอยากช่วยรันให้คุยกับเจ้าของก่อน

E. คำที่พิมพ์บ่อย (copy ไปใช้ได้)
   "ดึงของล่าสุดจาก main"
   "ตอนนี้อยู่ branch ไหน มีอะไรยังไม่ได้ save บ้าง"
   "validate ให้หน่อย แล้วอธิบาย error เป็นภาษาง่ายๆ"
   "commit, push, เปิด PR"
   "PR ของฉัน check เขียวหรือยัง"
   "ยกเลิกสิ่งที่เพิ่งแก้ในไฟล์ X" (Claude จะถามยืนยันก่อน)

ส่วนที่ 4  Dashboard (กระดานคิวงาน)
---------------------------------------------------------------------

Dashboard คืออะไร
  ตารางที่บอกว่างานใหญ่แต่ละชิ้น (ข้อสอบแต่ละชุด, ข้อสอบ bank ทีละ 30 หน้า, ตำราแต่ละเล่ม)
  ใครทำอยู่ ทำถึงไหน และอะไรยังว่าง สร้างจากไฟล์ใน jobs/ และ branch job/<id> บน GitHub
  เลยเห็นความคืบหน้าล่าสุดของทุกคน แม้งานนั้นยังไม่ merge

วิธีเปิด (เลือกแบบไหนก็ได้)
  1. ง่ายสุด: พิมพ์  /jobs  ใน Claude Code มันจะโชว์ตารางและส่งไฟล์ dashboard ให้
  2. พิมพ์บอก Claude: "เปิด dashboard ให้ดูหน่อย"
  3. เปิดเองใน Terminal (อยู่ในโฟลเดอร์ repo):
         python3 scripts/jobs.py dashboard
     แบบตัวอักษรจะขึ้นใน Terminal และแบบหน้าเว็บจะถูกสร้างที่ jobs/dashboard.html
     ดับเบิลคลิกไฟล์นั้นเพื่อเปิดใน browser
  หมายเหตุ: dashboard.html เป็นไฟล์ในเครื่องเรา ไม่ขึ้น GitHub
  เปิดใหม่ทุกครั้งที่อยากเห็นของล่าสุด (มันดึงข้อมูลจาก GitHub ใหม่ทุกครั้ง)

บรรทัดบนสุด เช่น
     95 jobs | 1061/5048 pages done | blocked: 1, on hold: 93, done: 1
  = มีงานทั้งหมด 95 ชิ้น ทำไปแล้ว 1061 จาก 5048 หน้า และนับจำนวนงานแต่ละ status
  ในหน้าเว็บจะเป็นแถบ progress bar

แต่ละคอลัมน์
  prio      ลำดับที่แนะนำ 1 = ควรทำก่อน 9 = ทีหลัง (เป็นคำแนะนำ ไม่ใช่คำสั่ง)
              ตอนนี้: 1 = ข้อสอบ Gen ของ MDCU75/76, 2 = MDCU73/74, 3 = รุ่นเก่ากว่า,
              4 = subspecialty, 5-6 = bank ใหญ่และเฉลยที่ยังจับคู่ไม่ได้
  status    สถานะงาน (ดูตารางด้านล่าง)
  size      ขนาดงานโดยประมาณ S = เล็ก, M = กลาง, L = ใหญ่, ? = ยังไม่รู้จำนวนหน้า
              (หน้าที่เป็นรูปสแกนนับเป็น 3 เท่า เพราะต้องอ่านจากรูป)
  pages     จำนวนหน้าของต้นฉบับ
  owner     คนที่ทำอยู่หรือทำล่าสุด  "-" = ยังไม่มีใคร
  id        ชื่องาน เช่น exam-mdcu76-gen-c-mcq
              = ข้อสอบ รุ่น MDCU76, General Sx, ชุด C, แบบ MCQ
              ในหน้าเว็บ ใต้ชื่องานมีลิงก์ "files" = เปิดโฟลเดอร์ไฟล์ของงานนั้นใน Drive
  bookmark  ที่คั่นหน้า: ทำถึงไหนแล้ว เช่น "p.12, Q1-45 saved"
              คนที่มาทำต่อจะเริ่มจากตรงนี้

ในหน้าเว็บมีตัวกรอง (filter) 3 อัน
  All statuses = เลือกดูเฉพาะ status เช่น To do อย่างเดียว
  All scopes   = General Sx / Subspecialty / Mixed
  All kinds    = Exam paper / Exam bank chunk / Textbook

ความหมายของ status
  todo         (To do)              ว่าง ใครก็หยิบได้
  in-progress  (In progress)        มีคนทำอยู่ ดูชื่อใน owner อย่าแย่งกันทำ
                                    ถ้าอยากช่วย ทักเจ้าของงานก่อน
  review       (Waiting for review) ทำเสร็จแล้ว แต่ PR ยังไม่ merge
                                    ไม่ได้แปลว่ามีคนตรวจอยู่ ถ้าว่าง ช่วยตรวจได้ (ส่วนที่ 6)
  done         (Done)               merge แล้ว
  blocked      (Blocked)            ติดอะไรบางอย่าง เช่น ยังไม่ได้ไฟล์ต้นฉบับ ดูเหตุผลใน bookmark
  on-hold      (On hold)            เจ้าของ repo สั่งพักไว้ ห้ามเริ่ม และห้ามเปลี่ยน status เอง

เลือกงานยังไง
  - ดูเฉพาะ todo แล้วเลือก prio เลขน้อยก่อน ถ้ามีเวลาน้อยเลือก size S
  - หรือถาม Claude: "แนะนำงาน todo ที่ควรทำ 5 อันแรก" (มันจะรัน jobs.py next ให้)
  - อยากรู้รายละเอียดงานไหน: "ขอดูรายละเอียดงาน <id>" (ต้นฉบับอยู่ไหน, เฉลยอยู่ไหน, log)
  - ห้ามแก้ไฟล์ใน jobs/ ด้วยมือ ให้ /jobs เปลี่ยนให้ เพื่อให้ dashboard ถูกต้อง

ส่วนที่ 5  กฎเหล็ก (ห้ามพลาด)
---------------------------------------------------------------------

1. ห้ามมีข้อมูลคนไข้ ทุกที่ รวมถึงใน raw/
   ห้าม: ชื่อคนไข้, HN/AN, วันเกิด, วันที่แบบเจาะจง, เลขวอร์ด/เตียง, เบอร์โทร,
         รูปที่เห็นหน้า ป้ายชื่อ หรือสายรัดข้อมือ
   ใช้แทน: อายุและเพศ เช่น "60s F" และสัปดาห์ของ rotation เช่น "W2"
   ชื่ออาจารย์ แพทย์ใช้ทุน และ resident ใส่ได้ และต้องเก็บไว้ตามต้นฉบับ
   ถ้า Claude เจอข้อมูลคนไข้ มันจะหยุดและให้คุณลบเอง

2. ห้ามแก้ main ตรงๆ ทำบน branch แล้วเปิด PR เสมอ

3. ห้ามแก้หรือลบไฟล์ของคนอื่นที่ merge แล้ว ยกเว้นแก้คำผิด
   ห้ามเปลี่ยนเลขข้อ หรือโจทย์ของข้อสอบที่ merge แล้ว

4. ห้ามตั้ง status เป็น human-verified ให้ไฟล์ที่ตัวเองทำ
   (ดูวิธี verify ในส่วนที่ 6)

5. เฉลยต้องบอกตามจริง: official = เฉลยจริง, recalled = จำมา, ai-derived = AI หา
   ห้ามทำให้เฉลยที่เดาดูเหมือน official

6. Claude ใช้ได้แค่สิ่งที่อยู่ในต้นฉบับ ถ้าเห็นมันเติมความรู้เอง ให้บอกให้ลบออก

7. ไฟล์ PDF ใหญ่ไม่ใส่ใน repo อยู่บน Google Drive (ลิงก์ใน sources/README.md)

8. ห้ามแชร์ password / token ให้ใคร และห้ามพิมพ์ลงแชต

ส่วนที่ 6  การตรวจงานกัน (review) และการ verify
---------------------------------------------------------------------

ทำไมต้องมี: GitHub แบบฟรีบังคับให้ "ต้องมีคนอนุมัติก่อน merge" ไม่ได้
ระบบเลยพึ่งการตกลงกันในกลุ่ม ช่วยกันทำตามนี้

ก่อน merge PR ของตัวเอง
  - check ต้องเขียว
  - ส่งลิงก์ PR ในกลุ่มไลน์ ให้เพื่อน 1 คนกดดูก่อน
    โดยเฉพาะ: งาน /jobs (ข้อสอบ ตำรา) และงาน synthesis ข้าม G
  - งานโน้ตส่วนตัวเล็กๆ merge เองได้เมื่อเขียว

เวลาเป็นคนตรวจ PR ของเพื่อน
  1. เปิดลิงก์ PR -> แท็บ "Files changed"
  2. สุ่มดู 5 ข้อหรือ 1-2 หน้า เทียบกับต้นฉบับ (PDF/โน้ต)
     ดูว่า: ตัวเลข ขนาดยา เลขข้อ ช้อยส์ เฉลย ตรงไหม มีข้อหายไหม มีข้อมูลคนไข้ไหม
  3. ผ่าน: กด "Review changes" -> Approve (หรือคอมเมนต์ว่า "ตรวจแล้ว ผ่าน")
     ไม่ผ่าน: คอมเมนต์ว่าข้อไหน/หน้าไหนผิด
  หรือให้ Claude ช่วย: "ช่วยเปิด PR #N สุ่ม 5 ข้อมาให้ฉันเทียบกับต้นฉบับ"

verify (ทำให้ไฟล์เป็น human-verified)
  ถ้าคุณเทียบไฟล์ไหนกับตำราหรือถามอาจารย์แล้ว บอกเจ้าของ repo ว่าไฟล์อะไร ตรวจอะไร
  ชื่อคุณจะถูกใส่เป็นคนตรวจ (verifier)


---------------------------------------------------------------------
ส่วนที่ 7  แผนที่โฟลเดอร์ (ไม่ต้องจำ ไว้เปิดดู)
---------------------------------------------------------------------

  README.md, CLAUDE.md   กฎและคำอธิบาย (Claude อ่านเองทุกครั้ง)
  INDEX.md               รายชื่อ topic และไฟล์ทั้งหมด
  raw/<ชื่อ>/            ต้นฉบับที่ไม่แก้คำ
  notes/<topic>/         case note และ concept note
  facts/<topic>/         facts ทีละบรรทัด, _merged.md = รวมทุกคน (สร้างอัตโนมัติ ห้ามแก้มือ)
  exams/<set>/           ข้อสอบแต่ละชุด + รูป
  digests/, synthesis/   สรุปสั้น และสรุปรวมข้าม G
  ward-guide/            survival guide และ tips ชีวิต ward
  textbook/<book>/       ตำราที่แกะออกมาทั้งเล่ม (เช่น chula-black-1)
  jobs/                  คิวงานใหญ่ หนึ่งไฟล์ต่อหนึ่งงาน
  templates/, prompts/   แบบฟอร์มไฟล์ และ prompt สำเร็จรูป
  scripts/, tests/       โปรแกรมตรวจและเครื่องมือ (ไม่ต้องแตะ)
  docs/                  คู่มือต่างๆ รวมถึงไฟล์นี้
  sources/               ลิงก์ PDF บน Drive


---------------------------------------------------------------------
ส่วนที่ 8  ติดปัญหา
---------------------------------------------------------------------

  check ขึ้นแดง
    -> พิมพ์ "PR ของฉัน check แดง ช่วยดูและแก้ให้หน่อย"

  push ไม่ได้ / "permission denied" / "authentication failed"
    -> ใน Terminal พิมพ์  gh auth login  ใหม่ แล้ว  gh auth setup-git
    -> ยังไม่ได้: เช็กว่ากด Accept invitation แล้ว

  "conflict" (มีคนแก้ไฟล์เดียวกัน)
    -> พิมพ์ "มี conflict ช่วยอธิบายและแก้ให้หน่อย" อย่ากดลบอะไรเองถ้าไม่แน่ใจ

  เผลอทำบน main
    -> พิมพ์ "ฉันเผลอแก้บน main ช่วยย้ายไป branch ใหม่โดยไม่ push"

  เผลอใส่ข้อมูลคนไข้ไปแล้ว (แม้ push ไปแล้ว)
    -> บอกเจ้าของ repo ทันที อย่าแก้เอง เพราะต้องลบออกจาก history ด้วย

  ไม่แน่ใจอะไรเลย
    -> ถาม Claude ว่า "อธิบายเหมือนฉันอายุ 5 ขวบ" หรือทักเจ้าของ repo
